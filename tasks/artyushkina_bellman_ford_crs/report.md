## 1. Введение
Алгоритм Беллмана-Форда — классический алгоритм поиска кратчайших путей в графе с произвольными весами ребер (включая отрицательные). Основные применения:
- Поиск кратчайших путей в транспортных сетях
- Анализ финансовых потоков с учетом издержек
- Оптимизация маршрутов в телекоммуникационных сетях
- Обнаружение отрицательных циклов в графах

Для работы с разреженными графами (большинство реальных графов) используется формат CRS, который позволяет эффективно хранить только ненулевые элементы.

## 2. Постановка задачи
Дан ориентированный взвешенный граф в формате CRS:
- `num_vertices`: количество вершин (n)
- `num_edges`: количество ребер (m)  
- `source_vertex`: исходная вершина для поиска кратчайших путей
- `row_ptr`: массив указателей начала строк (размер n+1)
- `col_idx`: массив индексов столбцов (размер m)
- `values`: массив весов ребер (размер m)

Требуется найти кратчайшие расстояния от исходной вершины до всех остальных вершин графа.

Тип входных данных:
```cpp
struct CRSGraph {
  std::vector<int32_t> row_ptr;
  std::vector<int32_t> col_idx;
  std::vector<double> values;
  int32_t num_vertices;
  int32_t num_edges;
  int32_t source_vertex;
};
```

Тип выходных данных:
```cpp
using OutType = std::vector<double>; // расстояния до всех вершин
```

## 3. Базовый алгоритм (Sequential)
Алгоритм Беллмана-Форда работает за время O(V×E), где V - число вершин, E - число ребер.

```cpp
// Инициализация расстояний
std::vector<double> distances(num_vertices, INFINITY);
distances[source_vertex] = 0.0;

// Релаксация ребер (V-1 раз)
for (int i = 0; i < num_vertices - 1; ++i) {
    bool updated = false;
    
    for (int u = 0; u < num_vertices; ++u) {
        if (distances[u] == INFINITY) continue;
        
        // Проход по всем исходящим ребрам из вершины u
        int start = row_ptr[u];
        int end = row_ptr[u + 1];
        
        for (int j = start; j < end; ++j) {
            int v = col_idx[j];
            double weight = values[j];
            double new_dist = distances[u] + weight;
            
            if (new_dist < distances[v]) {
                distances[v] = new_dist;
                updated = true;
            }
        }
    }
    
    // Оптимизация: если на итерации не было обновлений, выходим
    if (!updated) break;
}
```

## 4. Схема распараллеливания

### 4.1 Общий подход
В параллельной версии (MPI) распределяем вершины графа по процессам:
- Каждый процесс получает подмножество вершин
- Процессы выполняют релаксацию ребер для своих вершин
- Синхронизация расстояний после каждой итерации

### 4.2 Алгоритм распределения вершин
```cpp
// Распределение вершин по процессам равномерно
int vertices_per_process = num_vertices / world_size;
int remainder = num_vertices % world_size;

int my_vertices_start = rank * vertices_per_process + min(rank, remainder);
int my_vertices_end = my_vertices_start + vertices_per_process + (rank < remainder ? 1 : 0);
```

### 4.3 Схема параллельной работы алгоритма
1. **Инициализация MPI** - проверка состояния, инициализация при необходимости
2. **Распространение данных** - главный процесс (rank=0) рассылает структуру графа всем процессам
3. **Локальные вычисления** - каждый процесс обрабатывает свои вершины:
   - Проверяет расстояния до своих вершин
   - Обновляет расстояния для смежных вершин
4. **Глобальная синхронизация** - после каждой итерации:
   - Собираем минимальные расстояния со всех процессов (MPI_Allreduce с операцией MPI_MIN)
   - Проверяем, были ли обновления (MPI_Allreduce с операцией MPI_MAX)
5. **Финализация** - сбор результатов на главном процессе

### 4.4 Особенности реализации MPI
```cpp
// Ключевые MPI операции:
MPI_Bcast(&num_vertices, 1, MPI_INT32_T, 0, MPI_COMM_WORLD); // Рассылка количества вершин
MPI_Bcast(row_ptr.data(), num_vertices + 1, MPI_INT32_T, 0, MPI_COMM_WORLD); // Рассылка row_ptr
MPI_Allreduce(local_distances, global_distances, num_vertices, 
               MPI_DOUBLE, MPI_MIN, MPI_COMM_WORLD); // Синхронизация расстояний
```

### 5.2 Обработка особых случаев
1. **Пустой граф** (num_vertices = 0) - возвращаем пустой вектор
2. **Граф с одной вершиной** - возвращаем [0.0]
3. **Отключенные вершины** - расстояние = INFINITY
4. **Отрицательные веса** - алгоритм корректно обрабатывает
5. **Отрицательные циклы** - алгоритм не обнаруживает (требует дополнительной проверки)

### 5.3 Валидация входных данных
Проверяются:
- Корректность размеров массивов
- Некорректные индексы вершин
- Несогласованность row_ptr и num_edges
- Выход source_vertex за границы

## 7. Результаты и обсуждение

### 7.1 Корректность реализации

**SEQ тесты (все пройдены):**
1. **Простой граф** (4 вершины, 5 ребер) → [0.0, 1.0, 3.0, 6.0]
2. **Граф с отрицательными весами** → [0.0, -1.0, 2.0]
3. **Несвязный граф** → [0.0, 1.0, INFINITY, INFINITY]
4. **Граф с одной вершиной** → [0.0]
5. **Пустой граф** → []

**MPI тесты:**
- Базовые тесты проходят при запуске через mpirun
- Из-за проблем с Valgrind (обнаружение системных утечек) MPI тесты запускаются без Valgrind

**Валидация (все пройдены):**
1. Отрицательное количество вершин - невалидно
2. Некорректный source_vertex - невалидно
3. Несогласованность row_ptr и col_idx - невалидно
4. Индексы вершин за пределами - невалидно

### 7.2 Производительность

**Тестовые графы:**
- Маленький: 50 вершин, ~150 ребер
- Средний: 500 вершин, ~2500 ребер  
- Большой: 1000 вершин, ~5000 ребер

**Результаты (предварительные):**

| Граф | SEQ время (мкс) | MPI время (мкс) | Ускорение |
|------|-----------------|-----------------|-----------|
| Малый (50) | ~15 | ~25 | 0.6x |
| Средний (500) | ~1200 | ~800 | 1.5x |
| Большой (1000) | ~5000 | ~2800 | 1.8x |

**Наблюдения:**
1. **Накладные расходы MPI** значительны на маленьких графах
2. **Преимущество MPI** проявляется на графах от 500+ вершин
3. **Синхронизация** (MPI_Allreduce) занимает значительную часть времени
4. **Распределение по памяти** улучшает производительность на больших графах

### 7.3 Анализ проблем

1. **Проблема с Valgrind**: MPI оставляет "still reachable" блоки памяти, которые не являются реальными утечками, но вызывают ошибки в CI
   - **Решение**: Запускать MPI тесты без Valgrind, использовать suppression файлы
   
2. **Инициализация/финализация MPI**: Необходимо корректно управлять состоянием MPI
   - **Решение**: Использовать флаги для отслеживания, кто инициализировал MPI

3. **Распределение нагрузки**: Равномерное распределение вершин может быть неоптимальным для графов с разной степенью вершин
   - **Возможное улучшение**: Взвешенное распределение по количеству исходящих ребер
